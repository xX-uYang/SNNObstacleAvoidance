# runs/ —— 实验记录

本目录只入库**小体积文本结果**（`*.json` / `*.csv` / `*.md`）。
模型权重 `*.pt` / `*.pth` 已被 `.gitignore` 忽略，**不会上传**，
所以这里的目录通常只保留了指标，没有对应的权重文件。

## 哪些结果可以引用，哪些不可以

| 目录 | 内容 | 能否作为性能结论 |
| --- | --- | --- |
| `ann_image_v1/` | 图像-only 基线训练日志（`history.json`，20 轮） | ✅ 可以（训练过程） |
| `ann_image_v1_test/` | 图像-only 基线测试集指标与逐图预测 | ✅ **可以，这是当前唯一有效的性能结论** |
| `fusion_plumbing_only/` | SNN 融合**联调**训练日志 | ❌ 不可以 |
| `fusion_plumbing_only_test/` | SNN 融合**联调**测试指标 | ❌ **绝对不可以** |

### 为什么 `fusion_plumbing_only*` 不能引用

这两次实验使用的清单是 `data/carla_manifest_with_fake_snn.csv`，
其中的 `snn_*` 三列是**从真实标签反推出来的假概率**
（`snn_source = fake_debug_only_ground_truth_derived`）。
用它训练出来的 54.55% 精度既不代表融合有效，也不代表融合无效，
**唯一含义是"融合代码能跑通、不报错"**。

真实结论必须等 SNN 侧产出真实输出、用 `merge_snn_outputs.py` 回填
`snn_*` 三列后重跑才能得到。

## 当前有效结论（第一轮）

详见 [`ANN第一轮训练结果.md`](ANN第一轮训练结果.md)：

| 指标 | 数值 | 来源文件 |
| --- | --- | --- |
| 测试集 accuracy | 85.23% | `ann_image_v1_test/metrics.json` |
| 测试集 balanced accuracy | 84.96% | 同上 |
| 左 / 直行 / 右 召回率 | 87.10% / 77.78% / 90.00% | 同上 |
| 混淆矩阵 | `[[27,3,1],[5,21,1],[3,0,27]]` | 同上 |
| 模型前向 P50 / P95 / P99 | 3.64 / 4.89 / 5.05 ms | `ann_image_v1_test/benchmark.json` |

**已知局限**（摘自训练结果文档，引用时请一并说明）：

1. 测试集只有 88 张，单次划分，**没有多次随机种子重复实验**，
   ±1~2 个百分点的差异不具统计意义。
2. 数据仅来自单一批次（2026-04，625 张），场景多样性有限。
3. 延迟数值只是模型前向，**不含**图像读取、归一化、ROS 通信、
   SNN 等待与安全仲裁，不能当作端到端延迟。
4. 直行类召回率偏低（77.78%），主要失误是"直行被判成左/右"。

## 目录命名约定

后续新增实验请沿用：

```
runs/<实验名>/           训练产物（history.json）
runs/<实验名>_test/      在该实验权重上的测试集评估（metrics.json / predictions.csv）
```

并在提交前确认 `git status` 里**没有 `*.pt` / `*.pth`**。
