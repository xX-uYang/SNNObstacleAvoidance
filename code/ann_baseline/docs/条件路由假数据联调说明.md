# SNN 条件路由 + ANN 假数据联调说明

## 这次完成了什么

现在已经有一条可以实际运行的离线链路：

1. 从现有 CARLA 数据中挑选真实前视图片；
2. 生成临时的 SNN 接口数据，包括三类概率、校准置信度、膜电位、阈值、稳定性和延迟；
3. 在运行前检查两张表能否逐帧对应、图片是否存在、概率是否合计为 1、膜电位比例是否正确；
4. SNN 可信并且建议方向安全时，直接采用 SNN 结果，不执行 ANN 推理；
5. SNN 不可信、超时、膜电位没过阈值，或方向不安全时，才把图片交给 ANN；
6. 传感器数据无效，或危险已经近到不宜等待 ANN 时，写入安全兜底标记；
7. 保存每一帧为什么走这个分支、ANN 是否启动、最终输出是什么。

这只是“系统接线测试”，不是模型训练，也不是安全性证明。假 SNN 数据不能用于训练，联调结果也不能当成准确率。

## 三个主脚本的作用与运行顺序

### 第 1 个：make_fake_routing_data.py

作用：从 CARLA 数据中取真实前视图片，模拟目前还没有交付的 SNN 接口字段。它会生成 12 种场景，例如：

- 高置信度左转或右转；
- 第一名和第二名概率很接近；
- 膜电位没有达到阈值；
- 连续几帧的判断不稳定；
- SNN 超时或输出无效；
- 车道不安全；
- 传感器失效；
- 危险已经非常接近。

直接在 IDE 中运行本脚本即可。默认读取：

`E:\Intuition\carla_data\carla_data8.6`

默认输出：

`E:\Intuition\runs\conditional_routing_debug_v1\data`

### 第 2 个：validate_routing_data.py

作用：在模型运行前做“门卫检查”。如果接口字段缺失、两张表不是同一帧、概率和不为 1、预测标签不是最高概率类别、膜电位比例算错或图片不存在，它会停止并明确报错。

看到 `validation_passed: true` 才能进入第 3 步。

### 第 3 个：run_conditional_pipeline.py

作用：执行条件路由，并且只在 `CALL_ANN` 分支调用现有 ANN。

三个路由结果的白话意思：

- `SNN_DIRECT`：SNN 的证据足够强，方向也安全，直接采用；
- `CALL_ANN`：SNN 拿不准或证据有问题，让 ANN 看图片复核；
- `SAFE_FALLBACK`：输入已经不可靠，或时间太紧，不能正常给出方向，进入安全兜底。

当前使用的 ANN 是：

`E:\Intuition\runs\ann_image_v1\best.pt`

它只会输出左转、直行、右转，还不会真正输出刹车。因此日志中的 `brake_fallback` 只是“这里应该由后续安全控制模块处理”的占位标记，不代表刹车控制器已经完成，更不能直接接真车。

## 本次已经跑出的结果

使用 36 张真实 CARLA 图片和模拟的 SNN 字段，结果如下：

- SNN 直接输出：9 帧；
- 调用 ANN：21 帧；
- 安全兜底：6 帧；
- 明确没有调用 ANN：15 帧；
- ANN 只加载一次；
- ANN 平均单次推理约 8.48 毫秒，最大值约 66.90 毫秒（本次 CPU、样本很少，只说明程序能跑，不代表正式性能）。

输出文件：

- `data/carla_frames_fake_v1.csv`：CARLA 逐帧表，危险和车道字段为假数据；
- `data/snn_output_fake_v1.csv`：SNN 到路由器/ANN 的临时接口表；
- `data/fake_data_metadata.json`：说明假数据来源和用途；
- `result/routing_log_v1.csv`：逐帧完整决定记录；
- `result/summary.json`：本次联调汇总。

## 队友给出真实 SNN 输出后怎么替换

不要改 ANN 或路由脚本，优先让真实 SNN 导出一张与 `snn_output_fake_v1.csv` 同表头的 CSV。必须保证：

1. `sample_id + episode_id + frame_id` 与 CARLA 表完全相同；
2. `source_timestamp_ns` 是该图片的时间；
3. `predicted_action` 等于三个概率中的最大者；
4. 三个概率之和为 1；
5. 每类都给膜电位峰值、神经元阈值和二者之比；
6. `winner_threshold_crossed` 与获胜类别的膜电位是否过阈值一致；
7. 给出连续帧稳定性、稳定步数、输入/输出有效标记、延迟、模型版本；
8. `calibrated_confidence` 不能只是把 softmax 最大值换个名字，必须以后用独立验证集做校准。

替换 CSV 后，先运行第 2 个校验脚本，通过后再运行第 3 个路由脚本。

## 下一步应该做什么

1. SNN 同学按临时接口表导出 20 到 50 帧真实输出，先不追求大数据量；
2. ANN 同学用真实 SNN 表替换假表，确保系统仍然能跑通，并检查哪些帧触发 ANN；
3. 数据同学补齐可靠的障碍物、左右车道安全和 TTC 字段，因为路由不能只看模型置信度；
4. 三个人共同人工复核约 100 个关键片段，特别检查“错误但高置信度”的 SNN；
5. 等真实验证数据够用后，再标定置信度、概率差距、稳定性和 TTC 阈值；
6. 最后再决定是把 ANN 改成左/右/刹车三分类，还是把刹车单独做成安全控制规则。当前不要把临时阈值当成最终安全标准。
